# 发布管线（tools/publish）

把知识库的 13 集讲解做成**可直接投放 B站 / 抖音 / 小红书**的成片。
产物落在仓库根的 `dist/`（已进 `.gitignore`，不进版本库）；
`docs/assets/videos/` 那 13 集仓库内嵌资产与既有契约**完全不动**。

对标对象：`D:\Users\STM32\final-videos`（1920×1080@30fps、中文配音、SRT、
多比例封面、章节轴、B站投稿文案）。本管线把那一套搬到这边，并把动效做得更密。

---

## 快速开始

```bash
python tools/publish/build.py --check          # 校验旁白稿（不联网，秒级）
python tools/publish/build.py --list           # 列出各集字数与估算时长
python tools/publish/build.py --ep 02 --orient v h        # 渲一集两个方向
python tools/publish/build.py --all --orient v h --jobs 3 # 全量（15 GB 机器建议 3 路）
python tools/publish/build.py --cover          # 三种比例封面 + 贴边自检
python tools/publish/build.py --pack           # SRT / 章节轴 / 三平台投稿文案
python tools/publish/build.py --merge          # B站横屏合并长版
python tools/publish/build.py --verify         # 对标 STM32 的指标验收
python tools/publish/test_publish.py           # 管线自测（11 个用例）
```

依赖：`pillow`、`edge-tts`、`ffmpeg`/`ffprobe`，以及**能访问微软语音服务的网络**。
配音走在线服务、不是逐字节可复现，所以只在本地跑、产物不进版本库。

## 四个模块

| 文件 | 职责 |
|---|---|
| `voice.py` | edge-tts 配音 + **词级时间戳对齐** → 精确到字的字幕条 |
| `scenes.py` | 7 类场景渲染器：关键帧 + 补间 + 静态层缓存 |
| `engine.py` | 时间轴 / 逐帧合成 / 编码 / 混音 / SRT |
| `spec.py` | 旁白稿校验：禁用字形、放不下、时长 |
| `covers.py` / `pack.py` | 封面、章节轴、三平台文案、合并长版 |
| `measure.py` | 成片指标验收（对标 STM32） |

### `voice.py`：为什么自己写字幕切分

`edge_tts` 开 `boundary="WordBoundary"` 后，词边界的 `text` 拼起来等于旁白稿
去掉「标点与空白」后的字符序列。于是**每个字都能映射回精确时间**，字幕可以
按语义切分而不是按词边界硬切。两个坑都踩过并写进了自测：

- **版本号**：TTS 把 `2.2.3` 整体当一个词（点号算进词边界），所以对齐不能要求
  「逐字相等」，必须用双指针跳过稿里的标点。
- **缓存**：`marks` 的语义一变，旧缓存就是错的，而且不报错。缓存键必须带
  `ALIGN_VERSION`。

字幕硬指标按 **Netflix 简体中文规范 + BBC Subtitle Guidelines**：
每行 ≤16 汉字、每屏 ≤2 行、阅读速度 ≤9 汉字宽/秒、中文不用逗号句号。
拉丁标识符作为原子**永不劈开**（`setUpdatePerformanceListener` 整行放）。

### `scenes.py`：为什么要有「大面积持续动效」

第一版每个场景只做入场补间，结果实测**除多列对比外所有场景 90% 的时间是静止的**
（成片平均帧差 0.266，标杆 0.782）。根因是入场放完就冻住。

修法是给每个场景都加**大面积**持续动效——呼吸描边、扫光带、焦点块滑动、
流动光点、扫描线；再给字幕加**逐字高亮 + 跟读进度条**。
实测把平均帧差从 0.266 拉到 0.9~2.5（标杆 0.782），有动效占比从 17.9% 到 70~83%。

为什么必须「大面积」：验收按「帧差 > 0.3」统计，小范围光标闪烁在 180×320
采样下根本不够阈值——加了等于没加。

### 静态层缓存：把单帧成本从 850ms 压到 ~20ms

逐帧重画整幅 1080×1920 的话，一集 4 分钟要跑十几小时。这里把「已落定元素」
预渲染成若干底图（`Scene.base(k)`），每帧只做一次拷贝 + 画正在入场的那一个元素
+ 画持续动效。实测 ~20 分钟渲完一集（含配音），约 14× 实时。

## 已知限制

1. **配音不可逐字节复现**：edge-tts 是在线服务，同一稿两次合成音频字节不同。
   所以 `dist/` 不进版本库；`make assets` 那类「重跑必须逐字节一致」的校验不覆盖这里。
2. **单进程峰值内存 1~2 GB**：`--jobs` 在 15 GB 机器上别超过 3，否则编码阶段会
   `MemoryError`（报错会明确提示调小 `--jobs`）。
3. **平台规格属经验值**：分辨率/时长/封面比例来自调研（见评估报告），
   但抖音/小红书的官方规则页是 JS 单页应用、本次未取到正文。
   **引流规则与安全区像素值上线前需人工核对。**
4. **ep13 是全系列最后一集**：第 13 段 `next` 写的是收官语；若后续加 ep14 要改。
