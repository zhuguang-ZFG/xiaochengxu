# 文档写作契约（必读）

本知识库仿照「通往 AGI 之路（WayToAGI）」的知识库模式：**学习路径 + 分类文章 + README 索引**。
每篇文章是独立的 Markdown 文件，带 YAML 元数据，代码可复现，事实链接官方文档。

## 文件命名

- 目录：`docs/00-学习路线`、`01-入门`、`02-基础`、`03-进阶`、`04-云开发`、`05-发布`、`06-实战`、`07-资源`
- 文件：`NN-中文短名.md`，NN 为两位数序号，如 `01-认识小程序.md`
- 同一目录内序号连续、不重复

## YAML 元数据（每篇文章顶部，必须）

```yaml
---
title: 文章标题
description: 一句话摘要（README 索引会用）
category: 入门 | 基础 | 进阶 | 云开发 | 发布 | 实战 | 资源
tags: [标签1, 标签2]
difficulty: ★☆☆☆☆ | ★★☆☆☆ | ★★★☆☆ | ★★★★☆ | ★★★★★
reading_time: 10 分钟
updated: 2026-10-07
---
```

## 正文结构（固定）

1. **为什么读这篇** — 2~3 句：解决什么问题、前置知识
2. **正文** — 概念 → 代码示例 → 说明；代码必须可运行或可直接对照
3. **常见错误 / 避坑** — 至少 2 条真实踩坑点
4. **随堂测验** — 3~6 道场景选择题，答案用 `<details>` 折叠（见下方规范）
5. **验证** — 读者如何确认自己学会了（动手任务或自查清单）
6. **延伸阅读** — 官方文档链接 + 本库相关文章链接

### 随堂测验规范

每篇教学文章（`01-入门` 至 `07-资源`，不含 `00-学习路线` 下的元文章）必须在「常见错误 / 避坑」与「验证」之间包含 `## 随堂测验` 段落。

格式：

```markdown
## 随堂测验

**Q1**: 场景描述或问题？
- [ ] A. 选项
- [ ] B. 选项
- [ ] C. 选项
- [ ] D. 选项

<details><summary>答案</summary>

**B**. 一句话解释为什么，可附官方文档链接。

</details>
```

规则：
- 每篇 3~6 题，题目测**理解**而非纯记忆（场景题：「如果这样做会怎样」「哪条说法正确」）
- 每题必须有 `<details><summary>答案</summary>...</details>` 包裹，答案行以 `**X**.` 开头
- 至少一题涉及文章核心机制/原理
- `00-学习路线/` 下的元文章（学习路径总览、API 速查索引、FAQ）不要求随堂测验

## 视觉资产规范

- 图片/动画存放于 `docs/assets/`，文件名前缀标识用途：`screen-`（实物风格界面图 PNG）、`demo-`（动画演示 GIF）、`diagram-`（概念示意图 PNG）、`hero-`（门面横幅图 PNG）、`video-`（教学视频 MP4，存放于 `docs/assets/videos/`）
- 文档中引用用相对路径 `![说明](../assets/screen-hello.png)`，说明文字必须描述图中关键信息
- 动画演示 GIF：单帧 ≤ 640px 宽、总大小 ≤ 200KB、帧间延迟 300~600ms，只演示真实可复现的操作流
- 教学视频 MP4：720x1280 竖屏、24fps、H.264（yuv420p）、单集 ≤ 3MB，由 `python tools/gen_videos.py` 生成（含字幕帧，无需外部录音/录屏）
- 教学视频**必须用链接引用，不能用 `![]()` 内嵌**：GitHub 渲染仓库 Markdown 时会过滤 `<video>` 标签，`![](x.mp4)` 会显示为坏图。统一写成引用块，点击后由 GitHub 内置播放器播放：

  ```markdown
  > 📺 配套视频 · 第 N 集：[《标题》](../assets/videos/video-NN-slug.mp4)（时长 · 竖屏 720×1280）——一句话说明讲了什么。点击在 GitHub 内置播放器打开（仓库 Markdown 不支持内嵌播放器）。
  ```

- 实物风格图片为**渲染示意图**，非真实截图；标题说明处标注「示意图」避免误导
- 新增资产需在对应文档「验证」前插入，并同步更新本契约
- 硬限制由 `python tools/check_repo.py` 强制：GIF ≤200KB、视频 ≤3MB 且命名须为 `video-*.mp4`、MP4 必须含 `moov` 索引且每个 box 声明的长度不得越过文件末尾（渲染被中断只会留下 48 字节的 `ftyp+free+mdat` 空壳，体积检查对它完全瞎，但播放器打不开）、文档与 README 里写的「（NN 秒」必须与成片 `mdhd` 的实际时长一致（改时长要重渲染并同步文档，只改一边就会被拦）、README 指标表的数字必须与仓库实际计数一致、`docs/assets/`（含子目录）不允许存在未被任何文档引用的孤儿资产

## 技术规范

- 面向**微信小程序原生开发**（WXML/WXSS/JS/JSON + 微信开发者工具），以官方文档为准
- 代码块必须标注语言：`wxml`、`wxss`、`js`、`json`、`bash`
- 每个文件自成体系，可独立阅读；交叉引用用相对链接 `../02-基础/01-WXML数据绑定与渲染.md`（示例）
- 事实性内容必须链接微信官方文档 `https://developers.weixin.qq.com/miniprogram/dev/framework/`
- 截止 2026-10 的生态事实（写作时使用）：
  - 开发者工具 Stable 需 ≥ 1.06.2307260（Skyline 要求），普通开发建议用稳定版
  - Skyline 渲染引擎：各端支持版本见[官方兼容表](https://developers.weixin.qq.com/miniprogram/dev/framework/runtime/skyline/migration/compatibility.html)（安卓 8.0.33+、iOS 8.0.34+、工具 Stable 1.06.2307260+），基础库要求 ≥ 3.0.2
  - 默认渲染引擎仍是 WebView（2.x 基础库体系），Skyline 为可选新引擎
  - 云开发 = CloudBase（腾讯云），提供云函数/云数据库/云存储/云托管
  - 不用具体基础库小版本号做硬性断言，除非链接官方文档
- 术语：小程序（Mini Program）、开发者工具（DevTools）、WXML、WXSS、基础库、AppID、rpx、组件、API
- 中文正文；代码注释中文；专有名词保留英文原名

### 实战篇与示例工程必须逐行一致

README 与实战篇都声称「代码与教程逐行对应」，`check_example_sync()` 把这句话变成 CI 不变量：

- **实战篇里引用 `examples/<项目名>/` 文件的源码块**（`js`/`wxml`/`wxss`/`css`/`json`），必须与工程里对应文件逐行一致。改了一侧就得改另一侧；忽略缩进差异与块首的文件头注释（`// pages/index/index.js` 这类工程惯例，教程不写）
- **只给要点、不贴全文时**，标题或上文必须含「要点 / 节选 / 片段 / 省略 / 仅列」之一（如 `### index.wxss（要点）`），该块即豁免全等比对。不标注就按全文比对，会报漂移
- 比对只对**正文提到工程目录名**的文档生效：每个 `examples/` 下的子目录独立匹配——正文提到 `todo-miniprogram` 的文档与 todo 工程比对，提到 `navigation-miniprogram` 的与导航工程比对。入门/基础/进阶各篇也有 `app.json`、`index.js` 同名块，但那是各自独立的教学示例，不属于任何工程
- `bash`/`text` 块不参与比对（操作指令、目录树里出现文件名不构成节选关系）

### API 名必须真实存在，对 Promise 能力的断言必须与官方一致

写作风格里「API 名必须准确」由两项检查兜底。名单都在 `tools/data/`，由 `python tools/check_repo.py --update-api-list` 从[官方 API 索引页](https://developers.weixin.qq.com/miniprogram/dev/api/)与[官方 typings](https://github.com/wechat-miniprogram/api-typings) 抓取——不要手改；官方新增的接口刷新后连同提交。

- **`check_api_names()`**：正文与示例工程源码里出现的每个 `wx.<name>` 都必须在 `wx-api-names.txt`（507 个，两个来源取并集）里。本库曾把 npm 包 `miniprogram-api-promise` 的能力写成 `wx.` 下的接口并收进速查索引，读者照抄就是 `undefined is not a function`
- **`check_promise_claims()`**：`wx-api-promise.txt`（194 个）是官方 typings 里不传 success/fail/complete 即返回 Promise 的接口（[基础库 2.10.2 起](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/api.html)）。两条规则：
  - 对名单内的接口不能作「回调式 / 没有 Promise / 不支持 Promise」的平铺否定。实战篇曾这样警告 showModal，而示例工程正是直接 `await` 它——逐行一致校验只比代码文本，比不了正文对代码的断言
  - 不能 `await wx.<name>(` 名单外的接口：同步接口 await 了也拿不到更多东西；`wx.request`/`wx.uploadFile`/`wx.downloadFile`/`wx.connectSocket` 本身返回任务对象，await 到的不是结果
  - 带版本条件的正确说法（「基础库低于 2.10.2 需自行用 Promise 包装」）不会被误报——检查故意不认「封装/包装」这类词。反方向（说名单外的接口「返回 Promise」）也故意不查：最正确的那句话恰好同一行同时含规则与例外
- 两项检查都只看带 `wx.` 前缀的一级标识符：`wx.cloud.<name>` 只看到 `wx.cloud`，二级名字不在覆盖范围（云开发 API 的官方索引不在同一页，明说而不是假装覆盖）；正文提接口请一律写全 `wx.<name>`，裸写 `showModal` 检查看不见
- 确需把虚构名或错误断言当反面例子写出来（如 CHANGELOG 引用原话）：在该行末尾加 `<!-- api-ignore -->`，两项检查都跳过该行

## 写作风格

- 教程口吻：先给结论，再给证据（代码/文档），最后给验证
- 每个示例小而完整：先贴代码，再讲关键点
- 不用"我们""大家"等空泛称呼；直接说"你"
- 不写营销语、不灌水；每条内容必须有信息量
- 数字、版本、API 名必须准确；不确定就链接官方文档而非猜测

## 深度要求（避免"浅"）

每篇除「是什么 / 怎么做」外，必须至少包含一层**机制与原理**，禁止停留在 API 用法罗列：

- **原理层**：这个东西内部做了什么（如 setData 的深拷贝 → 跨线程通信 → 更新算法链路；wx:key 作为 diff 锚点）
- **为什么层**：为什么官方这样设计、为什么这条规则成立（如「拆组件优于减数据」源于算法成本与 Shadow 树规模正相关）
- **边界层**：什么情况下不生效、什么时候会出问题（如 tab 页不触发 onUnload、navigateBack 不重跑 onLoad）
- **量化层**（涉及性能/限制时）：给出官方数字（如主包 ≤2M、总分包 ≤30M）与测量手段（如 `setUpdatePerformanceListener`），而非"很快/很慢"这类模糊说法
- 深入内容必须链接官方文档出处，不臆造机制
- 例外：`00-学习路线/` 下的元文章（学习路径总览、API 速查索引、FAQ）和 `07-资源/` 下的资源索引篇不要求深度段落，但鼓励包含「为什么层」或「边界层」内容

## 学习体验设施

### PROGRESS.md（学习进度追踪）

仓库根目录的 `PROGRESS.md` 让读者勾选学习进度，按五个阶段分组，每篇文章一个 checkbox。格式：

```markdown
## 阶段① 认知
- [ ] [认识小程序](docs/01-入门/01-认识小程序.md)
...
```

规则：
- 文章列表必须与 README 教学顺序表一致——新增/删除文章时同步更新
- 底部有「出口标准自检」，与学习路径总览的各阶段出口标准对应
- 由 `check_progress_sync()` 校验一致性

### 知识图谱

`docs/assets/diagram-knowledge-graph.png` 是全局概念关系图（29 篇文章为节点，5 个阶段分组着色，前置关系为有向边），由 `tools/gen_diagrams.py` 生成。

节点表与边表都在 `gen_knowledge_graph()` 里，**标题上的篇数由节点表推导**，不要手写：v2.4.3 之前标题写「29 篇」而图里只画了 27 个节点（v2.0.0 新增的两篇实战文章从来没进过图），没有任何检查发现过。新增/删除教学文章时，同步节点表与边表即可，标题会自己跟着变。

必须在以下位置引用：
- `README.md` 的「学习路径」段落
- `docs/00-学习路线/01-学习路径总览.md`

### FAQ 文档

`docs/00-学习路线/03-FAQ.md` 汇总学习者高频问题，按阶段分类，每个 Q&A 用 `<details>` 折叠。格式：

```markdown
**Q**: 问题？

<details><summary>回答</summary>

答案正文，可附链接。

</details>
```

必须有 YAML 元数据（`category: 学习路线`），由 `check_faq_format()` 校验。

### 实战篇复盘要求

每篇实战文章（`docs/06-实战/`）必须包含：

- **架构决策复盘**表格，列名固定为 `决策 | 选它 | 放弃什么 | 什么情况会推翻`——重点是**权衡与可推翻条件**，不是好处罗列。由 `check_architecture_table()` 校验列名
- **踩坑回顾**表格（≥3 条），列名固定为 `症状 | 原因 | 修复`——先写用户看到的现象，再写根因，最后写修复方式。由 `check_pitfall_table()` 校验列名
- 章节顺序：踩坑回顾在「常见错误 / 避坑」之后、「随堂测验」之前（与正文结构第 3-4 条一致）

## 视觉资产的生成（可复现）

- 资产生成脚本位于 `tools/`：`render.py`（渲染管线：2x 超采样抗锯齿、阴影、波纹、插值缓动、跨平台中文字体解析）、`gen_animations.py`（全部动画定义）、`gen_videos.py`（教学视频：场景脚本 + 字幕帧 + ffmpeg 合成）
- 运行 `python tools/gen_animations.py` 可重新生成 `docs/assets/` 下全部动画；`python tools/gen_videos.py` 生成 `docs/assets/videos/` 下教学视频（需 `pip install imageio-ffmpeg`）
- **资产必须与脚本输出逐字节一致**，CI 会在 `windows-latest` 上重跑四个生成脚本并比对（`tools/check_assets_fresh.py`）。所以：改了脚本必须重跑并一并提交，手工改资产会被打回
- **字体不写死平台路径**：`render.font_file()` 按 Windows（微软雅黑）→ macOS（苹方）→ Linux（Noto CJK / 文泉驿）顺序查找首个存在的中文字体，粗体缺失时退化为常规体；都找不到时报错并给出安装命令。新增平台请在 `render.FONT_CANDIDATES` 补充路径，不要改回硬编码
  - 推论：**同一份脚本在不同平台渲染出的像素不同**（字体不同），所以资产比对只能在生成时所用的平台上跑（当前是 Windows）。换平台重新生成 = 全库资产字节全变，需要连同 CI 的 `runs-on` 一起改
- 视频渲染走**生成器 + ffmpeg rawvideo 管道**逐帧流式写入：720x1280 RGB 单帧 2.7MB，75 秒 × 24fps 若一次性持有帧列表需约 5GB 内存，必须保持 `yield` 而非 `append` 的写法
- 视频编码必须带 `-threads 1`：libx264 的帧级多线程会让同一份输入在不同核数的机器上编出不同字节（实测 1/2/4/8 线程四个哈希全不同），不加这行 CI 的资产比对会永远失败。代价约 +7 秒/集
- 视频合成**必须先写临时文件、成功之后才落地**（`tempfile.mkstemp` + `shutil.move`），不许把 `docs/assets/videos/` 里的最终路径直接交给 ffmpeg。ffmpeg 是一启动就把输出文件建出来的，进程被 kill 时仓库里就留下一个只有 `ftyp+free+mdat` 头的 48 字节空壳——体积检查放行、播放器打不开，v2.4.3 就是这么漏了 4 集。落地用的临时文件也别放在 `docs/assets/` 里（会被孤儿检查算成资产）
- 字幕文案**不许用渲染字体画不出来的字符**（`✓ ✗ ✅ ❌ 👆 ▶` 等在微软雅黑下都是空心方块）。`gen_videos.caption()` 会用 `.notdef` 位图比对提前拦住，`tools/test_gen_videos.py` 扫字面量；要表达「对/错」用 `√ ×`，要引导视线用已经画得出来的 `→ ← ↑ ↓ ● ★ ·`
- **图上与 README 上的统计数字必须数出来，不许手打**：篇数/题数/集数/工程数一律取 `check_repo.repo_stats()`（全仓库唯一一份计数）。`check_readme_stats()` 会拿 README 的指标表逐格比对，`check_readme_videos()` 会顺着「对应文章」找到那一集成片、用 `mdhd` 里的真实时长逐行核对表格。为什么管这么严：「视觉资产 57 个」在加视频之后错了很久，`gen_statics.py` 那行写着「数字从仓库里数出来」的注释底下是一排字面量——抄来的数字一定会过期，而读者看不出它过期
- 动画制作规范：**关键帧 + 补间帧**，禁止整屏帧替换。补间用 `render.build()`（交叉淡化）或 `render.retween_gif()`（对已有帧自动补间）；单文件 ≤200KB，`build`/`retween_gif` 会自动降补间帧数与调色板色数以满足限制
- 修改动画应改脚本而非手改图片，保证可复现；新增动画后运行 `python tools/gen_animations.py`（含补间后处理）
