# 网络请求与数据

## 为什么读这篇

小程序不能没有后端。这篇解决三件事：**怎么发请求**（wx.request + 域名白名单）、**怎么本地存数据**（storage 系列）、**登录态怎么建立**（wx.login 流程）。这些是任何真实项目的地基，也是「联调后端」时错误最多的部分。

前置知识：[JS 逻辑层与数据驱动](../02-基础/03-JS逻辑层与数据驱动.md)、[页面生命周期与事件](../02-基础/04-页面生命周期与事件.md)。

## wx.request 基础

![网络请求生命周期](../assets/diagram-request-lifecycle.png)

```js
wx.request({
  url: 'https://api.example.com/list',
  method: 'GET',
  data: { page: 1 },
  header: { 'content-type': 'application/json' },
  success(res) {
    console.log(res.statusCode, res.data);
  },
  fail(err) {
    console.error('请求失败', err);
  }
})
```

要点：

- `data`：GET 拼 query，POST 放 body
- `res.statusCode`：HTTP 状态码；`res.data`：响应体
- `header`：默认 `application/json`；传 FormData 需改 content-type

### 域名白名单（头号坑）

域名白名单演示（渲染示意图动画：模拟器勾选「不校验合法域名」请求成功 → 真机未配置域名报 url not in domain list → 后台配置 HTTPS 域名后真机成功）：

![域名白名单演示](../assets/demo-domain.gif)

真机环境，**请求域名必须是 HTTPS 且在 mp 后台配置过**：

- 后台：「开发 → 开发设置 → 服务器域名」添加 request 合法域名
- 域名要求：HTTPS、已备案、不能带端口/路径、需下载校验文件验证归属
- 开发工具里可以勾选「详情 → 本地设置 → 不校验合法域名」绕过，但**真机仍会拦截**，上线前必须配好

配置域名后**发布生效有延迟**（约几分钟到十几分钟），联调要留时间。

## Promise 封装

原生回调写法难维护，统一封装成 Promise + async/await：

```js
// utils/request.js
const BASE_URL = 'https://api.example.com';

function request(path, method = 'GET', data = {}) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: `${BASE_URL}${path}`,
      method,
      data,
      success(res) {
        if (res.statusCode >= 200 && res.statusCode < 300) {
          resolve(res.data);
        } else {
          reject(new Error(`HTTP ${res.statusCode}`));
        }
      },
      fail: reject
    });
  });
}

export const get = (path, data) => request(path, 'GET', data);
export const post = (path, data) => request(path, 'POST', data);
```

使用：

```js
import { get } from '../../utils/request';

Page({
  data: { list: [], loading: true },
  async onLoad() {
    try {
      const res = await get('/list', { page: 1 });
      this.setData({ list: res.list });
    } catch (err) {
      console.error(err);
    } finally {
      this.setData({ loading: false });
    }
  }
})
```

注意：基础库 2.10.2 起，大多数异步 API 不传 success/fail/complete 就直接返回 Promise，但 `wx.request`/`wx.uploadFile`/`wx.downloadFile`/`wx.connectSocket` **例外**——它们本身有返回值（请求任务对象，用于中断、监听进度），[官方明确要求](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/api.html)开发者自行封装，所以这层封装是必需品。想批量转换可用官方 npm 包 [`miniprogram-api-promise`](https://github.com/wechat-miniprogram/miniprogram-api-promise)（`promisifyAll(wx, wxp)`），但手写封装能顺手把状态码判断、错误归一塞进去，最可控。

## 本地存储

同步版（简单场景，数据量小）：

```js
wx.setStorageSync('user_info', { name: '小明' });
const info = wx.getStorageSync('user_info');
wx.removeStorageSync('user_info');
wx.clearStorageSync();
```

异步版（大数据量、避免阻塞）：

```js
wx.setStorage({
  key: 'user_info',
  data: { name: '小明' },
  success() { /* 写成功 */ }
});
```

注意：

- 同步版会阻塞逻辑层，大对象（> 几百 KB）用异步版
- 单 key 上限 1MB，总上限 10MB（超了报错）
- storage 是**本地**存储，跨设备不同步；需要云端数据用云开发或自建后端

典型用途：缓存 token、用户信息、列表快照（离线可看）。

## 登录态：wx.login 全流程

小程序免注册登录的标准链路：

```mermaid
sequenceDiagram
  participant 小程序
  participant 微信服务器
  participant 业务后端
  小程序->>微信服务器: wx.login() 拿 code
  微信服务器-->>小程序: code（5分钟有效）
  小程序->>业务后端: 请求 login 接口，传 code
  业务后端->>微信服务器: code + appid + secret → code2session
  微信服务器-->>业务后端: openid + session_key
  业务后端-->>小程序: 自定义 token
  小程序->>小程序: token 存 storage，后续请求带 token
```

```js
// 小程序端
wx.login({
  success: async (res) => {
    if (res.code) {
      const { token } = await post('/login', { code: res.code });
      wx.setStorageSync('token', token);
    }
  }
})
```

关键点：

- `code` 有效期 5 分钟，且**只能换一次** session，用完作废
- `code2session` 必须由**后端**调用（要用 appsecret，绝不能放小程序端）
- 后端据此拿 `openid`（用户在小程序内的唯一身份）建账号、发 token
- 业务接口校验 token；token 过期用 `wx.checkSession` 判断 session 是否还有效

## 网络请求的安全边界

小程序的网络请求有三层安全机制，理解它们才能正确排查「请求不通」：

1. **域名白名单（编译期）**：`wx.request` 的目标域名必须在「mp 后台 → 开发管理 → 服务器域名」配置。这是微信客户端在发起请求前校验的——域名不在白名单，请求根本不会发出。设计目的是防止小程序偷偷请求未审核的服务器（数据泄露/钓鱼）。开发时可勾选「不校验合法域名」跳过
2. **HTTPS 强制（传输层）**：生产环境必须 HTTPS（TLS 1.2+）。HTTP 请求只在开发模式下可用。这是为了防止中间人攻击篡改小程序与服务端之间的数据
3. **Session 机制（应用层）**：`wx.login` 拿到 code → 服务端用 code 换 session_key + openid → 服务端生成自定义 token 返回小程序。session_key 是服务端间的密钥，**绝不能传到小程序端**（[登录态](#登录态wxlogin全流程)）。泄露 session_key = 泄露用户数据解密能力

三层中任何一层出问题，表现都是「请求失败」，但排查方向完全不同。

## 请求的健壮性

### 防重复提交

```js
Page({
  data: { submitting: false },
  async onSubmit() {
    if (this.data.submitting) return;   // 防连点
    this.setData({ submitting: true });
    try {
      await post('/order', this.data.form);
    } finally {
      this.setData({ submitting: false });
    }
  }
})
```

### 超时与重试

```js
// 封装里加超时
function request(path, method = 'GET', data = {}) {
  return new Promise((resolve, reject) => {
    let done = false;
    const timer = setTimeout(() => {
      done = true;
      reject(new Error('timeout'));
    }, 10000);
    wx.request({
      url: `${BASE_URL}${path}`,
      method, data,
      success(res) {
        if (done) return;
        clearTimeout(timer);
        resolve(res.data);
      },
      fail(err) {
        if (done) return;
        clearTimeout(timer);
        reject(err);
      }
    });
  });
}
```

重试策略：GET 类幂等请求失败可重试 1~2 次（间隔递增），POST 提交类请求**不要盲目重试**（可能重复下单），提示用户手动处理。

## 常见错误 / 避坑

1. **真机请求失败、模拟器正常**：99% 是域名白名单问题——检查后台服务器域名配置、域名是否备案、是否 HTTPS。
2. **`fail` 回调里没有 res.statusCode**：网络错误（域名不通/超时）走 fail，HTTP 错误（404/500）走 success 但 statusCode 非 2xx——**两个分支都要处理**，不能只在 success 里判断。
3. **wx.login 的 code 多次使用**：code 一次性，误用两次会 40029 报错；重新 wx.login 拿新 code。
4. **把 appsecret 写进小程序代码**：任何人反编译都能看到，账号安全直接沦陷；secret 只在后端。
5. **同步存储大对象卡顿**：setStorageSync 阻塞逻辑层，大对象换异步版。
6. **POST 没设 content-type**：后端收不到 JSON body 或收到字符串；header 明确 `'content-type': 'application/json'`（默认已是，改 FormData 时注意）。

## 随堂测验

**Q1**: 开发者在模拟器里调试接口一切正常，但发布到真机后所有请求都失败了。最可能的原因是什么？
- [ ] A. 真机网络不支持 wx.request API
- [ ] B. 请求域名没有在小程序后台配置为合法域名，或域名不是 HTTPS
- [ ] C. 真机的基础库版本太低不支持网络请求
- [ ] D. 模拟器默认使用了不同的 API 地址

<details><summary>答案</summary>

**B**. 真机环境强制校验域名白名单（必须 HTTPS 且在 mp 后台配置），模拟器可以勾选「不校验合法域名」绕过，但真机不行。

</details>

**Q2**: 关于 `wx.login` 获取的 `code`，以下说法正确的是？
- [ ] A. code 可以反复使用，只要没过期就能多次换取 session
- [ ] B. code 只能使用一次，用完就作废；再次需要必须重新 wx.login 拿新 code
- [ ] C. code 可以直接在前端换取 openid，不需要后端参与
- [ ] D. code 的有效期是 24 小时

<details><summary>答案</summary>

**B**. code 有效期 5 分钟且只能换一次 session，用完即废；多次使用会报 40029 错误。code2session 必须在后端调用（需要 appsecret）。

</details>

**Q3**: 以下关于 wx.request 的 `success` 和 `fail` 回调，哪个说法是正确的？
- [ ] A. HTTP 404/500 错误走 `fail` 回调，网络断开走 `success` 回调
- [ ] B. `success` 回调里不需要判断 statusCode，只要进了 success 就是请求成功
- [ ] C. HTTP 404/500 走 `success` 回调（需要判断 statusCode），网络断开/超时走 `fail` 回调
- [ ] D. POST 请求必须设置 `content-type: 'application/x-www-form-urlencoded'` 才能发送 JSON

<details><summary>答案</summary>

**C**. HTTP 状态码异常（404/500）仍走 success 回调但 statusCode 非 2xx，网络错误（域名不通/超时）走 fail；两个分支都要处理。

</details>

**Q4**: 一个提交表单的页面需要防止用户连续点击导致重复提交，以下哪种方案最合理？
- [ ] A. 给 button 加 `loading="{{true}}"` 永远显示加载中
- [ ] B. 在 data 里设 `submitting` 标志位，点击时判断并锁定，请求完成后释放
- [ ] C. 给 button 加 `disabled="{{true}}"` 永远禁用
- [ ] D. 在 bindtap 里用 setTimeout 延迟 3 秒再提交

<details><summary>答案</summary>

**B**. 用 `submitting` 标志位实现防连点：点击时锁定、请求完成（finally）后释放，既防重复又不影响正常提交。

</details>

**Q5**: 关于小程序本地存储（wx.setStorageSync），以下哪个说法是正确的？
- [ ] A. 本地存储的数据会自动同步到用户的其他设备
- [ ] B. 单个 key 上限 10MB，总共可以存 100MB
- [ ] C. 单个 key 上限 1MB，总上限 10MB；大对象建议用异步版避免阻塞逻辑层
- [ ] D. 同步版和异步版功能完全一样，没有任何区别

<details><summary>答案</summary>

**C**. 单 key 上限 1MB、总上限 10MB；同步版会阻塞逻辑层，大对象（> 几百 KB）应使用异步版。storage 是本地存储，跨设备不同步。

</details>
