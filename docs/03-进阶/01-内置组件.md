# 内置组件

## 为什么读这篇

小程序 UI 由「内置组件」拼装而成——没有 HTML 标签，一切皆是组件。这篇是高频组件的速查手册：每个组件的核心属性、一个可用示例、一个易错点。写页面时按需查阅即可。

前置知识：[WXML 数据绑定与渲染](../02-基础/01-WXML数据绑定与渲染.md)、[WXSS 样式与 rpx](../02-基础/02-WXSS样式与rpx.md)。

## 组件通用规则

高频组件速查（概念示意图：10 个高频内置组件及其用途，通用规则见下）：

![高频内置组件速查](../assets/diagram-components.png)

所有组件都支持：

- `id` / `class` / `style`：样式定位
- `data-*`：自定义数据（事件里经 `event.currentTarget.dataset` 读取，见 [页面生命周期与事件](../02-基础/04-页面生命周期与事件.md)）
- `bind*` / `catch*`：事件绑定（`bindtap`、`catchlongpress` 等）
- `hidden`：显示/隐藏

命名规则：标签名一律小写（`view`、`text`、`button`），属性值中布尔值必须用 `{{true}}`/`{{false}}`（字符串 `"false"` 恒为真，详见 [WXML 数据绑定](../02-基础/01-WXML数据绑定与渲染.md)）。

## 组件行为的设计原理

组件速查之前，先理解几个高频「为什么」——知道机制后，遇到怪异行为就能自己推断原因，而不是靠试错。

![组件行为原理](../assets/diagram-component-mechanism.png)

![input 受控 vs 非受控](../assets/demo-component-behavior.gif)

### input 为什么是受控组件

小程序的 input 是**受控组件**：输入框的 `value` 由逻辑层的 `data` 决定，而不是由用户输入直接决定。

机制链路：

```text
用户按键 → 渲染层 input DOM 更新 → 触发 bindinput
                                      ↓
                    逻辑层收到 event.detail.value
                                      ↓
                    必须 this.setData({ inputValue: value }) 才能同步
```

如果 `bindinput` 里不调 `setData`，渲染层的 DOM 值和逻辑层的 `data.inputValue` 就会**分叉**——DOM 显示用户输入的内容，但 `data.inputValue` 还是旧值。后果：

1. **光标位置错乱**：框架在 setData 时会重置光标位置，如果 data 和 DOM 不一致，光标会跳到开头
2. **表单提交丢数据**：提交时读 `data.inputValue` 拿到的是旧值，不是用户实际输入的
3. **双向绑定失效**：其他依赖 `inputValue` 的视图不会更新

这就是为什么 input 示例里总是 `value="{{inputValue}}"` + `bindinput="onInput"` 成对出现——前者把 data 推到 DOM，后者把 DOM 的变化回传到 data。

### swiper 为什么不能 auto-height

swiper 的内部实现是**横向滚动容器 + `position: absolute` 的 swiper-item**。每个 slide 脱离文档流叠放在同一位置，通过 translateX 切换可见项。

因为 swiper-item 全部 `absolute`，父容器 swiper **没有内在高度**——它不知道子元素有多高。如果你不显式设高度，swiper 会塌缩为 0。

这是增量渲染模型的取舍：如果 swiper 要支持 auto-height，就需要先测量所有 slide 的高度取最大值，但这与「懒加载 slide 内容」的设计冲突。所以官方选择要求开发者显式指定高度。

```css
.swiper { height: 400rpx; }  /* 必须显式指定 */
```

### scroll-view 为什么必须固定高度

scroll-view 的滚动计算依赖 `scrollHeight - clientHeight`：

- `scrollHeight`：内容总高度（由子元素撑开）
- `clientHeight`：容器可见高度（由 CSS 决定）

如果没有显式高度，`clientHeight` 会自动扩展到等于 `scrollHeight`（容器跟着内容撑开），差值为 0——无法滚动。

```css
.scroll-area { height: 500rpx; }  /* 或 calc(100vh - 200rpx) */
```

### image 默认 320×240 的原因

image 组件在未加载完成时会显示一个 320×240 的占位区域。这是向后兼容早期版本的设计——确保图片加载前页面布局不偏移（CLS = 0）。如果图片实际尺寸不同，加载完成后会重新布局。建议：始终给 image 设 `width` 和 `height` 或 `mode` 属性，避免加载前后的布局跳动。

## view：布局容器

万能容器，相当于 div。可滚动（`scroll-y` 属性）但不常用（有专用 scroll-view）。

```wxml
<view class="card" hover-class="card-hover">
  卡片内容
</view>
```

常用属性：`hover-class`（手指按下时的样式类）、`hover-stay-time`（松开后保持时间，默认 70ms）。

注意：`view` 默认 `display: block`；flex 布局记得在父容器设 `display: flex`。

## text：文本

```wxml
<text class="title">标题文本</text>
<text selectable>这段可以长按复制</text>
<text decode>&amp;nbsp;</text>
```

- `selectable`：允许长按选中复制
- `decode`：解码 `&nbsp;` 等实体
- `text` 内支持嵌套 `text`

注意：**只有 `text` 组件内的文本可以长按复制**，`view` 里的不行；「复制订单号」这类需求用 `text selectable`。

## button：按钮

```wxml
<button type="primary" size="mini">主要按钮</button>
<button type="default" loading="{{loading}}">加载中</button>
<button type="warn" disabled="{{!canSubmit}}">警告按钮</button>
<button open-type="share">转发给好友</button>
<button open-type="contact">打开客服</button>
```

- `type`：primary（绿）/ default / warn（红）
- `size`：default / mini
- `loading`：显示菊花
- `open-type`：开放能力——`share`（分享）、`contact`（客服）、`getUserInfo`（获取用户信息）、`getPhoneNumber`（获取手机号，需企业主体）等
- `hover-class`：按压态

注意：button 默认带微信样式（圆角、边框），想自定义要覆盖它的样式并留意 `::after` 边框：

```css
button::after { border: none; }
```

## input / textarea：输入

受控更新演示（渲染示意图动画：bindinput 不 setData 导致值丢失/光标乱跳，setData 回填 value 后正常）：

![input 受控更新演示](../assets/demo-input.gif)

```xml
<input
  value="{{keyword}}"
  placeholder="搜索"
  bindinput="onInput"
  bindconfirm="onSearch"
  maxlength="20"
  confirm-type="search"
/>
```

```js
onInput(e) {
  this.setData({ keyword: e.detail.value });
}
```

- `bindinput`：输入时触发，`e.detail.value` 为当前值（**受控写法**：存进 data）
- `bindconfirm`：按确认键
- `confirm-type`：键盘右下角按钮（search/send/done…）
- `type`：text/number/idcard/digit 等

textarea 类似，多 `auto-height`（自动增高）。

注意：**input 的值必须通过 data 回填**，否则光标跳动/值丢失（受控组件模式）；不要直接在 wxml 里写死 value。

## image：图片

```wxml
<image src="{{item.cover}}" mode="aspectFill" lazy-load />
```

- `src`：网络地址、本地路径或 base64
- `mode`：裁剪/缩放模式，最常用 `aspectFill`（填满裁剪）与 `widthFix`（宽定高自动）
- `lazy-load`：懒加载（滚动到附近才加载）
- `bindload` / `binderror`：加载成功/失败回调

注意：image 默认有固定尺寸（320×240），**不设宽高会变形**；`mode="widthFix"` 配 `width: 100%` 是「宽度铺满、高度自适应」的经典组合。

## swiper：轮播

```wxml
<swiper indicator-dots autoplay interval="3000" circular>
  <swiper-item wx:for="{{banners}}" wx:key="id">
    <image src="{{item.url}}" mode="aspectFill" class="banner-img" />
  </swiper-item>
</swiper>
```

常用：`indicator-dots`（圆点）、`autoplay`、`interval`（间隔 ms）、`circular`（循环）、`bindchange`（切换事件，`e.detail.current` 为当前索引）。

注意：`swiper` 高度要显式设置，内容撑不开高度；item 用 `swiper-item` 包裹，不能直接用 view。

## scroll-view：滚动区域

触底加载演示（渲染示意图动画：滚动到容器底部触发 bindscrolltolower 加载下一页数据）：

![scroll-view 触底加载演示](../assets/demo-scroll.gif)

```xml
<scroll-view scroll-y class="list" bindscrolltolower="loadMore">
  <view wx:for="{{list}}" wx:key="id">{{item.title}}</view>
</scroll-view>
```

- `scroll-y` / `scroll-x`：开启方向滚动（容器需限高）
- `bindscrolltolower`：滚动到底触发（做「加载更多」）
- `enable-flex`：允许内部 flex 布局

注意：页面级滚动不需要 scroll-view；scroll-view 用于**页面内固定高度区域的滚动**，配合 `bindscrolltolower` 做分页。普通长列表性能敏感时，`scroll-view` 配合虚拟列表（官方 [recycle-view](https://developers.weixin.qq.com/miniprogram/dev/extended/component-plus/recycle-view.html) 或 Skyline 的按需渲染）更好。

## navigator：页面跳转

```wxml
<navigator url="/pages/detail/detail?id={{item.id}}" open-type="navigate">
  查看详情
</navigator>
```

- `url`：目标路径（相对或绝对）
- `open-type`：navigate（默认压栈）/ redirect / switchTab / reLaunch / navigateBack
- 传参格式与 `wx.navigateTo` 一致：`?key=value`

注意：跳 tabBar 页面必须用 `open-type="switchTab"`；`navigate` 不能跳 tab 页，会失败无提示。

## rich-text：富文本

渲染 HTML 字符串（如后端返回的文章内容）：

```wxml
<rich-text nodes="{{htmlContent}}" />
```

- `nodes`：HTML 字符串或节点数组
- 只支持白名单内的标签（`<img>`、`<p>`、`<a>` 等），script/style 不解析

注意：`rich-text` 内图片尺寸由 `nodes` 里的样式决定，后端返回的 HTML 常需要清洗（去内联大图、加安全域名）。复杂交互场景（如点击图片预览）建议用 `web-view` 或自己解析节点。

## web-view：网页容器

在小程序里直接嵌 H5 页面：

```wxml
<web-view src="https://example.com/page" />
```

注意：**web-view 会铺满整个页面**（不能与其他组件混排），域名需在 mp 后台配置业务域名；业务含大量 H5 逻辑时用 web-view 快速迁移，但支付、登录等能力受限，交互体验不如原生。

## 常见错误 / 避坑

1. **image 不设宽高**：默认 320×240 导致图片变形；列表封面用 `width:100% + mode="widthFix"`，头像用固定宽高 + `aspectFill`。
2. **input 值不回填 data**：直接 `e.detail.value` 显示后输入框光标乱跳；必须 `this.setData({ keyword: e.detail.value })` 受控更新。
3. **swiper 高度塌陷**：不设高度时轮播区变一条线；给 swiper 显式高度（如 300rpx）。
4. **scroll-view 限高缺失**：scroll-y 不生效是因为容器没高度；给容器 `height` 或 flex:1。
5. **button 自定义样式被默认样式干扰**：微信 button 自带边框（::after）与圆角，重置需 `button::after{border:none}` + 覆盖 background。
6. **把富文本直接渲染成 view**：`view` 不解析 HTML 标签，`<p>` 会当作文本显示；必须用 `rich-text`。

## 随堂测验

**Q1**: 页面有一个 `<swiper>` 轮播组件，开发者没有给 swiper 设置高度，里面放了 3 张 banner 图。真机上最可能出现什么现象？
- [ ] A. 图片正常显示，swiper 自动撑开到图片高度
- [ ] B. swiper 区域变成一条线，几乎看不到内容
- [ ] C. 图片竖向排列溢出屏幕
- [ ] D. swiper 显示默认占位图

<details><summary>答案</summary>

**B**. swiper 高度不会被子元素撑开，必须显式设置高度（如 300rpx），否则轮播区塌陷成一条线。

</details>

**Q2**: 需求是「用户长按可以复制订单号」，以下哪种写法是正确的？
- [ ] A. `<view selectable>{{orderNo}}</view>`
- [ ] B. `<text selectable>{{orderNo}}</text>`
- [ ] C. `<text decode>{{orderNo}}</text>`
- [ ] D. `<view hover-class="copy">{{orderNo}}</view>`

<details><summary>答案</summary>

**B**. 只有 `text` 组件内的文本支持长按复制，`view` 上加 `selectable` 无效；`decode` 是解码实体字符用的。

</details>

**Q3**: 开发者在页面写了一个 `<scroll-view scroll-y>` 做列表滚动，但真机上怎么滚都滚不动。最可能的原因是？
- [ ] A. scroll-view 没有设置 `enable-flex`
- [ ] B. scroll-view 容器没有设置高度（如 height 或 flex:1）
- [ ] C. 列表数据太多导致 scroll-view 自动禁用滚动
- [ ] D. 应该用 `scroll-x` 而不是 `scroll-y`

<details><summary>答案</summary>

**B**. `scroll-y` 要求容器有明确高度才能生效，没有限高则滚动区域无限大、无法触发滚动。

</details>

**Q4**: 以下关于 `input` 组件的写法，哪个会导致光标乱跳或输入值丢失？
- [ ] A. `<input value="{{keyword}}" bindinput="onInput" />`，onInput 里 `this.setData({ keyword: e.detail.value })`
- [ ] B. `<input value="{{keyword}}" bindinput="onInput" />`，onInput 里只 `console.log(e.detail.value)` 没有 setData
- [ ] C. `<input placeholder="搜索" bindinput="onInput" />`，onInput 里 setData 存值
- [ ] D. `<input value="{{keyword}}" bindconfirm="onSearch" />`，onSearch 里 setData 存值

<details><summary>答案</summary>

**B**. input 是受控组件，`bindinput` 回调里必须 `setData` 回填 value，否则输入框的值和光标状态会异常。

</details>

**Q5**: 小程序的 input 组件被称为「受控组件」。以下哪个选项最准确地解释了「受控」的含义？
- [ ] A. input 的样式必须由 WXSS 控制，不能用内联 style
- [ ] B. input 的显示值由逻辑层 data 决定，用户输入必须经 bindinput → setData 回传 data，否则 DOM 与 data 分叉导致状态异常
- [ ] C. input 只能放在 form 组件内部，不能独立使用
- [ ] D. input 的值只能由框架自动设置，开发者不能手动修改

<details><summary>答案</summary>

**B**. 「受控」的核心机制是：渲染层拥有 DOM，逻辑层拥有 data。input 的 `value` 是从 data 推到 DOM 的「建议值」，用户输入后通过 `bindinput` 事件把新值回传到逻辑层，逻辑层 `setData` 后再推回 DOM——形成单向数据流闭环。如果中间断了（不 setData），两层数据就会分叉。

</details>
