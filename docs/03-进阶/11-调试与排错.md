# 调试与排错：从 console 到线上监控

## 为什么读这篇

代码写对了 80%，剩下 20% 的时间在排错。新手最常见的困境：报错看不懂、模拟器正常真机挂了、线上出了 bug 却拿不到现场。

这篇把「排错链路」讲完整：**开发者工具面板怎么用 → 真机调试为什么必须做 → 运行时性能怎么量化 → 线上错误和日志怎么回收**。前置知识：[JS 逻辑层与数据驱动](../02-基础/03-JS逻辑层与数据驱动.md)（数据流，排错时先怀疑它）。

## 一、开发者工具：六块面板的用途地图

工具（[调试器文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/debug.html)）左侧的调试器就是排错主战场，六块面板各管一件事：

| 面板 | 用途 | 什么时候用 |
|---|---|---|
| Console | 日志与报错（`console.log` 都在这里） | 一切排错的第一步：先看有没有异常 |
| Wxml | 视图层节点树 + 每个节点的绑定数据 | 界面不对时：查渲染结果与数据是否同步 |
| AppData | 当前页面 `data` 的实时快照，可**直接改** | 怀疑数据流问题时：手动改值验证视图联动 |
| Network | 网络请求、耗时、状态码 | 请求失败、加载慢 |
| Storage | 本地缓存内容（同步/异步两种） | 缓存读不到、被清空 |
| Audits | 一键性能体检（[性能审计](https://developers.weixin.qq.com/miniprogram/dev/framework/audits/performance.html)） | 上线前跑一轮，按报告逐项修 |

排错顺序建议固定为：**Console 看报错 → AppData 验证数据 → Wxml 验证渲染 → Network 验证链路**。多数「界面没变」的 bug，在 AppData 一步就能定位：是 `data` 没变（逻辑层问题）还是变了没渲染（绑定问题）。

### 1.1 机制：为什么模拟器「正常」不等于真机「正常」

模拟器是桌面浏览器内核 + 开发模式，与真机有四类系统性差异：

1. **能力差异**：部分 API（如部分设备能力）模拟器直接不支持或行为不同
2. **性能差异**：桌面渲染快，真机低端机才暴露卡顿
3. **网络差异**：模拟器不校验「请求域名白名单」（工具可勾选跳过校验），真机严格校验
4. **隐私差异**：授权弹窗、隐私协议在模拟器上的触发时机与真机不同

所以契约惯例是：**功能在模拟器验证，上线前必过真机**。

## 二、真机调试：拿到真机现场

预览二维码只能「看」，要「调试」用真机调试（[真机调试文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/remote-debug.html)）：真机运行、工具侧开调试器，Console/Network/AppData 全量可查，还能直接调试线上版本（远程调试）。

真机上想看 console 输出，两个入口：

```js
// vConsole：真机上的迷你调试面板（右上角小绿标）
wx.setEnableDebug({
  enableDebug: true
});
```

- 开发/体验阶段可用 `wx.setEnableDebug` 打开 vConsole（[官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/base/debug/wx.setEnableDebug.html)）
- 预览时也可在工具里勾选「打开调试」，效果相同
- **发布前务必移除或条件关闭**：vConsole 会展示内部日志，且有性能开销

![真机调试与 vConsole](../assets/demo-debug.gif)

真机调试演示：模拟器点击「真机调试」→ 真机拉起小程序 → 打开 vConsole 面板，日志逐条滚动 → 出现一条 JS 错误（红）→ 面板收起。

## 三、运行时性能：用数字代替感觉

「感觉卡」不可复现；性能问题要用指标说话。两个官方入口：

**1. 一键审计**：工具 → 详情 → 性能分析（Audits），自动给出首屏时间、setData 频率、耗时 Top 项，[官方性能审计文档](https://developers.weixin.qq.com/miniprogram/dev/framework/audits/performance.html)。

**2. 自定义指标上报**：关键路径耗时打进官方性能体系，后台「性能分析」可聚合：

```js
// 上报一个自定义性能指标（ID 与含义你在后台「自定义上报」里定义）
wx.reportPerformance(502, 150);   // 比如：502 = 首屏数据加载耗时，150ms
```

[wx.reportPerformance 官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/base/performance/wx.reportPerformance.html)。更细的运行时测量（setData 单次耗时、渲染耗时）用 `wx.getPerformance` 的 PerformanceObserver（[官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/base/performance/wx.getPerformance.html)）订阅 `measure` 条目。

## 四、线上错误与日志：出事能查到现场

线上 bug 的难点是拿不到现场。三件套配合：

**1. 全局错误兜底**——`App.onError` / `App.onUnhandledRejection`（[App 构造器文档](https://developers.weixin.qq.com/miniprogram/dev/reference/api/App.html#onError-function)）：

```js
// app.js：兜住未捕获错误，主动上报
App({
  onLaunch() {},
  onError(err) {
    console.error('全局错误:', err);
    // 上报到自己的监控（wx.request 到业务后端 / 云函数入库）
    wx.request({
      url: 'https://your-monitor.example.com/report',
      method: 'POST',
      data: { err: String(err), scene: wx.getLaunchOptionsSync() }
    });
  },
  onUnhandledRejection(e) {
    console.error('未处理的 Promise 拒绝:', e.reason);
  }
})
```

**2. 实时日志**——`wx.getRealtimeLogManager`（[官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/base/debug/wx.getRealtimeLogManager.html)）：写日志，线上真机出问题时可让用户反馈，后台「实时日志」查现场；生产版默认按后台配置抽样收集，不是全量。

```js
const log = wx.getRealtimeLogManager();
log.info('页面加载', { page: 'index' });
log.error('请求失败', { url: '/api/todos', statusCode: 500 });
```

**3. 错误分析 + sourcemap**：报错信息里只有压缩后代码的行列号，把 sourcemap 上传到工具（[sourcemap 文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/sourcemap.html)）后，后台「错误分析」里能看到还原的源码位置，定位效率差一个量级。

## 常见错误 / 避坑

1. **真机上 console 不输出**：不是代码没跑，是没开 vConsole/真机调试。先确认调试通道再怀疑逻辑。
2. **模拟器能请求、真机全部失败**：域名没配白名单或没上 HTTPS（真机强制校验），与代码无关。看 Network 面板的报错文案区分。
3. **AppData 里改值无效**：改的是「当前快照」；若页面逻辑在 onShow 里重新赋值，改动会被覆盖。改完要手动触发相关回调确认。
4. **`console.log` 打印对象显示 `...` 展开不完整**：对象包含循环引用或超大数组，用 `JSON.stringify(obj, null, 2)` 分段打印定位。
5. **vConsole 泄露到正式版**：用环境判断包裹 `wx.setEnableDebug`，或发布前从代码移除；体验版/开发版可保留。

## 随堂测验

**Q1**: 开发者在模拟器上调试时一切正常，但真机预览时网络请求全部失败。以下哪个是最可能的原因？
- [ ] A. 真机的微信版本太低
- [ ] B. 真机强制校验域名白名单（HTTPS + mp 后台配置），模拟器可勾选跳过校验
- [ ] C. 真机不支持 wx.request API
- [ ] D. 代码在真机上编译出了不同的结果

<details><summary>答案</summary>

**B**. 模拟器可以勾选「不校验合法域名」绕过限制，真机强制校验 HTTPS 和域名白名单；这是模拟器与真机的系统性差异之一。

</details>

**Q2**: 在开发者工具的 AppData 面板里手动修改了某个 data 值，界面确实变了，但刷新页面后值又恢复了。以下哪个解释最准确？
- [ ] A. AppData 面板有 bug，修改不会持久化
- [ ] B. AppData 改的是当前快照，页面逻辑在 onShow 等生命周期里会重新赋值覆盖手动修改
- [ ] C. data 的值被微信服务器同步覆盖了
- [ ] D. 手动修改后需要调用 this.setData 才能生效

<details><summary>答案</summary>

**B**. AppData 修改的是当前快照，如果页面逻辑在 onShow 等生命周期里重新赋值，改动会被覆盖；它适合临时验证数据流，不是持久修改。

</details>

**Q3**: 线上小程序出现了偶发 bug，用户反馈时已经无法复现。以下哪种组合方案最适合排查这类问题？
- [ ] A. 只在模拟器里反复测试，等 bug 自然复现
- [ ] B. 用 App.onError 兜底全局错误 + wx.getRealtimeLogManager 记录实时日志 + 上传 sourcemap 还原源码位置
- [ ] C. 让用户截图报错信息
- [ ] D. 给每个用户发一个开发者工具账号

<details><summary>答案</summary>

**B**. 线上 bug 需要三件套：`App.onError` 捕获未处理错误、`getRealtimeLogManager` 记录现场日志、sourcemap 将压缩后行列号还原为源码位置，组合使用才能事后追查。

</details>

**Q4**: 关于 `wx.setEnableDebug`，以下说法正确的是？
- [ ] A. 正式版也应该保持开启，方便收集用户反馈
- [ ] B. 它只在正式版生效，体验版无法使用
- [ ] C. 发布前应移除或条件关闭，因为 vConsole 会展示内部日志且有性能开销
- [ ] D. 它会自动在正式版关闭，不需要手动处理

<details><summary>答案</summary>

**C**. vConsole 会展示内部日志（可能泄露敏感信息）且有性能开销；发布前必须移除或用环境判断包裹，体验版/开发版可保留。

</details>
