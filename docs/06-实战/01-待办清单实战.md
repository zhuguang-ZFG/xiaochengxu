## 项目设计

**功能清单**：

1. 待办列表展示（未完成/已完成筛选）
2. 新增待办（输入 + 按钮）
3. 切换完成状态（点击勾选）
4. 删除待办（滑动或按钮）
5. 数据存云数据库，**按用户隔离**（每个人只看到自己的）

**技术选型**：原生小程序 + 云开发（云函数 + 云数据库）。全程不写后端服务器。

**目录结构**：

todo-miniprogram/
├── app.js / app.json / app.wxss
├── cloudfunctions/
│   └── todo/                 # 唯一云函数：所有增删改查走这里

**为什么数据操作走云函数而不是前端直连数据库**：虽然云数据库前端也能读写，但统一走云函数可以集中做校验（长度、类型），且后续加功能（分享、统计）不用改权限模型。这符合 [云数据库](../04-云开发/03-云数据库.md) 的安全建议。

### 架构决策复盘：这个项目为什么这样设计

每个决策都有 tradeoff，想清楚它比照抄代码更重要：

表：待办清单的架构决策与取舍

| 决策 | 选它 | 放弃什么 | 什么情况会推翻 |
|---|---|---|---|
| 数据走云函数（非前端直连） | 校验集中、权限模型简单、后续扩展不用改集合权限 | 少写些样板代码；云函数有调用延迟与免费额度限制 | 只读公开数据、无安全要求的场景，前端直连更快 |
| 单页面 + 单云函数 | 学习曲线最低，一个文件讲完全部增删改查 | 代码组织粗糙；action 分支多了难维护 | 功能变多后拆多个云函数（getTodo/toggleTodo…） |
| openid 做归属字段 | 数据隔离开箱即用，无需自建用户表 | 无法跨设备同步用户偏好（openid 是应用级身份） | 需要用户资料、跨端登录时引入 unionid/用户表 |
| 集合权限设「仅管理端可读写」 | 双保险：前端 SDK 完全不能读写，云函数是唯一入口 | 所有数据操作都必须经过云函数，读多写少的场景会多一次函数调用 | 需要前端直连读取公开数据时，改用安全规则 |
| 新增用幂等键 + 确定性 `_id` | 网络重试、重复点击不会产生重复待办 | 多一个 `clientToken` 字段和一次哈希计算 | 业务本身就允许重复提交（如流水记录）时不需要 |

复盘方式：每做完一个项目，把你做的每个「选 A 不选 B」列出来，写下推翻条件。这是从「会做」到「会设计」的分水岭。

### 踩坑回顾：开发过程中遇到的真实问题

| 症状 | 原因 | 修复 |
|---|---|---|
| 云函数调用报「function not found」 | 写了云函数代码但没有在开发者工具里右键「上传并部署」 | 右键 cloudfunctions/todo →「上传并部署：云端安装依赖」；每次改完云函数都要重新部署 |
| 不同用户看到了彼此的待办 | 云函数查询没加 openid 条件，返回了全集合数据 | 每个查询/写操作都带 `openid` 条件，集合权限设「仅管理端可读写」做双保险 |
| 真机上所有用户的数据混在一起 | `getWXContext()` 返回字段是大写 `OPENID`，写成小写 `openid` 会拿到 `undefined`，归属条件形同虚设 | 用 `const { OPENID } = cloud.getWXContext()`；测试 mock 也返回大写字段 |
| 网络抖动或连点两次后出现两条相同待办 | 客户端重试被当成两次新请求，服务端每次都 `add` | 客户端为一次提交生成 `clientToken`，服务端用它派生确定性 `_id`，重复写入按幂等成功处理 |
| 点击待办项没反应 | 用了 `catchtap` 但事件处理函数名拼错（大小写不一致） | 小程序事件名区分大小写；`catchtap` 会阻止冒泡，如果父级也需要收到事件就用 `bindtap` |
| 切换筛选 tab 后列表没刷新 | 在 `onLoad` 里获取数据，但 tab 切换不重新触发 `onLoad` | 把数据获取放到 `onShow` 里，或在 tab 切换的回调里手动调一次获取函数 |
| app.js 里环境 ID 写了占位符 | 忘记把 `'你的环境ID'` 替换成真实 ID，`wx.cloud.init` 静默失败 | 开通云开发后复制环境 ID，替换 app.js 里的占位符；project.config.json 的 `appid` 同理 |

每个坑都对应一个前面教程里的知识点。踩坑不可怕，可怕的是踩了同一个坑两次。

## 第二步：云函数 todo

**cloudfunctions/todo/index.js**（一个函数处理所有操作，action 区分）：

*代码状态：可运行*

```js
const crypto = require('crypto');
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const db = cloud.database();
const todos = db.collection('todos');

function checkTitle(title) {
  if (typeof title !== 'string') throw new Error('标题不合法');
  const value = title.trim();
  if (!value || value.length > 100) throw new Error('标题不合法');
  return value;
}

function checkToken(clientToken) {
  if (typeof clientToken !== 'string' || !clientToken || clientToken.length > 64) {
    throw new Error('幂等键不合法');
  }
  return clientToken;
}

function checkId(id) {
  if (typeof id !== 'string' || !id) throw new Error('待办 ID 不合法');
  return id;
}

function todoId(openid, clientToken) {
  return 'todo_' + crypto.createHash('sha256')
    .update(openid + '\n' + clientToken)
    .digest('hex')
    .slice(0, 24);
}

exports.main = async (event = {}) => {
  const { action, payload = {} } = event;
  const { OPENID } = cloud.getWXContext();   // 身份由微信注入，payload 里的 openid 不可信
  if (!OPENID) throw new Error('缺少用户身份');

  const log = cloud.logger();
  const openidHash = crypto.createHash('sha256').update(OPENID).digest('hex').slice(0, 12);

  switch (action) {
    case 'list': {
      const { status, page = 1, size = 20 } = payload;
      const where = { openid: OPENID };
      if (status !== 'all') where.done = status === 'done';
      const res = await todos
        .where(where)
        .orderBy('createTime', 'desc')
        .skip((page - 1) * size)
        .limit(size)
        .get();
      return { code: 0, list: res.data };
    }
    case 'add': {
      const title = checkTitle(payload.title);
      const clientToken = checkToken(payload.clientToken);
      const id = todoId(OPENID, clientToken);
      try {
        await todos.add({
          data: { _id: id, openid: OPENID, clientToken, title, done: false, createTime: Date.now() }
        });
        log.info({ event: 'todo.add', action, openidHash, id, duplicated: false });
        return { code: 0, id };
      } catch (err) {
        const res = await todos.where({ _id: id, openid: OPENID }).limit(1).get();
        if (res.data.length === 0) throw err;
        log.info({ event: 'todo.add', action, openidHash, id, duplicated: true });
        return { code: 0, id, duplicated: true };
      }
    }
    case 'toggle': {
      const id = checkId(payload.id);
      const res = await todos.where({ _id: id, openid: OPENID }).update({
        data: { done: !!payload.done }
      });
      log.info({ event: 'todo.toggle', action, openidHash, id, updated: res.stats.updated });
      return { code: 0, updated: res.stats.updated };
    }
    case 'remove': {
      const id = checkId(payload.id);
      const res = await todos.where({ _id: id, openid: OPENID }).remove();  // 只能删自己的
      log.info({ event: 'todo.remove', action, openidHash, id, removed: res.stats.removed });
      return { code: 0 };
    }
    default:
      log.warn({ event: 'todo.unknown', openidHash, action: String(action).slice(0, 64) });
      throw new Error(`未知操作: ${action}`);
  }
};
```

安全要点（对应 [云数据库权限](../04-云开发/03-云数据库.md)）：

- **身份只认 `OPENID`**：归属字段来自 `cloud.getWXContext().OPENID`，`payload.openid` 即使传了也被忽略
- **每个操作都带 `openid` 条件**：toggle/remove 用 `where({ _id: id, openid: OPENID })`，别人改不了、删不了你的数据
- **校验输入类型与长度**：`title` 必须是字符串且非空、不超过 100 字；`clientToken` 必须是 1–64 字符；`id` 必须是非空字符串
- **新增幂等**：`clientToken` 与 `OPENID` 一起哈希成确定性 `_id`。同一次提交重试时 `_id` 冲突，服务端查出原记录并返回同一个 `id`，不会写第二条
- **日志脱敏**：只记录 `openidHash`、事件名、记录 id 等可检索字段，不记录明文 openid、标题和幂等键
- 集合权限设为「仅管理端可读写」：前端 SDK 完全不能读写，所有数据操作只能走云函数

上传部署后，在云开发控制台建 `todos` 集合，权限选「仅管理端可读写」。控制台本身属于管理端，仍然可以查看和修改数据；被挡住的是小程序前端 SDK。

### index.js

*代码状态：可运行*

```js
function newClientToken() {
  return Date.now().toString(36) + '-' + Math.random().toString(36).slice(2, 10);
}

Page({
  data: {
    title: '',
    status: 'all',
    list: []
  },

  onShow() {
    this.fetchList();
  },

  async fetchList() {
    const res = await this.callTodo('list', { status: this.data.status });
    this.setData({ list: res.list });
  },

  callTodo(action, payload) {
    return new Promise((resolve, reject) => {
      wx.cloud.callFunction({
        name: 'todo',
        data: { action, payload },
        success: (res) => {
          if (res.result.code === 0) resolve(res.result);
          else reject(new Error(res.result.errMsg));
        },
        fail: reject
      });
    });
  },

  onInput(e) {
    this.addToken = '';   // 输入变了，上一次未完成的提交不再复用幂等键
    this.setData({ title: e.detail.value });
  },

  async onAdd() {
    const title = this.data.title.trim();
    if (!title || this.submitting) return;
    this.submitting = true;
    this.addToken = this.addToken || newClientToken();   // 失败重试复用同一幂等键
    try {
      await this.callTodo('add', { title, clientToken: this.addToken });
      this.addToken = '';
      this.setData({ title: '' });
      await this.fetchList();
    } finally {
      this.submitting = false;
    }
  },

  async onToggle(e) {
    const { id, done } = e.currentTarget.dataset;
    await this.callTodo('toggle', { id, done: !done });
    this.fetchList();
  },

  async onRemove(e) {
    const { id } = e.currentTarget.dataset;
    const { confirm } = await wx.showModal({ title: '确认删除？' });
    if (!confirm) return;
    await this.callTodo('remove', { id });
    this.fetchList();
  },

  onFilter(e) {
    const { status } = e.currentTarget.dataset;
    this.setData({ status });
    this.fetchList();
  }
})
```

## 常见错误 / 避坑

1. **云函数未部署就调用**：`callFunction` 报 `FunctionName not found`；每次改完云函数重新上传部署。
2. **环境 ID 填错**：init 的 env 与函数所在环境不一致，调用失败或数据进错环境。
3. **toggle/remove 忘了 openid 条件**：`doc(id).update` 不带归属条件，等于任何人能改任何数据（云函数模式下没有前端权限兜底，**必须自己加**）。同时确认字段名是大写 `OPENID`，小写 `openid` 会得到 `undefined`。
4. **删除用 catchtap 而点击用 bindtap**：删除按钮不 catch 会冒泡触发整行 toggle，出现「点删除变完成」。
5. **onShow 每次刷新列表**：从筛选页/后台返回会重新拉数据——这正是我们想要的（数据最新），但注意高频操作时合理节流。
6. **`await wx.showModal(...)` 拿不到 `confirm`**：异步 API 不传 success/fail/complete 时直接返回 Promise（[基础库 2.10.2 起](https://developers.weixin.qq.com/miniprogram/dev/framework/app-service/api.html)），resolve 值就是 success 回调的那个 `res`——本工程 `onRemove` 正是这么写的。拿不到的两种情况：基础库低于 2.10.2（需自行用 Promise 包装），或传了回调又去 await（有回调就按回调方式执行，无返回值）。`wx.request`/`wx.uploadFile`/`wx.downloadFile` 本身有返回值（请求任务对象），不适用此规则。
7. **重复提交产生重复待办**：只在客户端 `trim` 不够，网络超时重试、连点都会重复 `add`；用 `clientToken` + 确定性 `_id` 做幂等，重试返回同一个 `id`。
8. **日志泄露用户隐私**：不要把明文 openid、待办标题、`clientToken` 原样写进日志；用 `openidHash` 和事件字段，既能检索又不泄露内容。

**Q2**: 在待办列表的 WXML 中，删除按钮用 `catchtap` 而不是 `bindtap`，原因是：
- [ ] A. `catchtap` 响应速度更快
- [ ] B. `catchtap` 阻止事件冒泡，防止删除时同时触发整行的 toggle 事件
- [ ] C. `catchtap` 支持长按删除
- [ ] D. `bindtap` 不能在 `wx:for` 循环中使用

<details><summary>答案</summary>

**B**. 删除按钮如果不用 `catchtap` 阻止冒泡，点击删除会同时触发父元素的 `bindtap`（toggle），出现「点删除变完成」的 bug，参见[常见错误](#常见错误--避坑)第 4 条。

</details>

**Q3**: 这个项目选择把所有数据操作统一走云函数而不是前端直连数据库，最主要的考虑是什么？
- [ ] A. 前端直连数据库性能太差
- [ ] B. 统一走云函数可以集中做校验，且后续扩展不用改权限模型
- [ ] C. 前端直连数据库的代码量更大
- [ ] D. 云函数可以绕过微信的所有限制

<details><summary>答案</summary>

**B**. 统一走云函数的好处是校验集中、权限模型简单、后续扩展（分享/统计）不用改集合权限，参见[架构决策复盘](#架构决策复盘这个项目为什么这样设计)。

</details>

**Q4**: 用户 A 和用户 B 分别使用这个待办清单小程序，各自添加了待办事项。关于数据隔离，以下哪个说法是正确的？
- [ ] A. 所有用户看到同一个待办列表
- [ ] B. 数据隔离靠集合权限实现，与 openid 无关
- [ ] C. 云函数中每个操作都用 openid 做 where 条件，保证 A 看不到 B 的数据
- [ ] D. 数据隔离需要额外建一张用户权限表

<details><summary>答案</summary>

**C**. 云函数中 list/toggle/remove 每个操作都带 openid 条件查询，保证每个用户只能操作自己的数据，参见[安全要点](#第二步云函数-todo)。

</details>

**Q5**: 客户端为一次「添加」生成 `clientToken`，服务端用它和 `OPENID` 派生确定性 `_id`。网络超时后客户端用同一个 token 重试，会发生什么？
- [ ] A. 新增第二条相同待办
- [ ] B. 服务端报主键冲突，客户端显示失败
- [ ] C. 服务端发现 `_id` 已存在，返回原来的记录 id，列表仍只有一条
- [ ] D. 服务端覆盖原记录

<details><summary>答案</summary>

**C**. 同一个 `OPENID + clientToken` 必然算出同一个 `_id`；第二次 `add` 主键冲突后，服务端查出原记录并返回同一个 `id`，所以重试是幂等的，参见[安全要点](#第二步云函数-todo)。

</details>

**Q6**: 云函数里写 `const { openid } = cloud.getWXContext()`，在真机上最可能发生什么？
- [ ] A. 正常拿到用户 openid
- [ ] B. `openid` 为 `undefined`，因为官方字段名是大写 `OPENID`
- [ ] C. 代码编译报错
- [ ] D. 只能拿到 unionid

<details><summary>答案</summary>

**B**. `cloud.getWXContext()` 返回的字段是 `OPENID` / `APPID` / `UNIONID`，小写解构会得到 `undefined`，归属条件随之失效，参见[踩坑回顾](#踩坑回顾开发过程中遇到的真实问题)。

</details>
